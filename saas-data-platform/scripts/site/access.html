One file decides what each role sees.

Private by default

Forget a rule and the data disappears. It doesn't leak.

No tag, no column

A column with no classification is hidden from every role. A new column stays inside HR's own tables until someone decides who may see it.

Private models

Raw HR models are private to People Analytics. A revenue model that references them fails to compile.

Under 5, hidden

No people metric is shown for fewer than 5 people, because a number about two people is a number about a person.

Keys, not records

Revenue joins people through a bridge that holds two hashed keys and nothing else.

The proof

The tests run on every build.

Each test returns the rows that break its rule, so zero rows is a pass. Loosen the policy, say by giving analysts raw pay, and the build fails.

{{proof_table}}
Ownership

Every table has an owner.

Generated from dbt's manifest when the site is built, so it can't drift from the code. Certified tables have enforced contracts: change a column's name or type and the build fails.

In production

On BigQuery, the warehouse enforces the same rules.

Locally, DuckDB has no users, so the boundaries are schemas, views and tests. In production the same policy becomes access the warehouse itself enforces.
